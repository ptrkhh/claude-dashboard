# Dashboard Chat Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Chat button on every running session card opens that session's conversation inside the dashboard, talking only to `cdash-agent`, for Claude Code, Codex and OpenCode.

**Architecture:** The agent runs one *hub* per chatted session. A hub takes normalized events from an *engine*, numbers them, keeps them in memory, fans them out to WebSocket clients, and owns the held-message queue. There are two engines: the Claude engine tails the session transcript and the session state file and types through tmux; the native engine talks NDJSON over a unix socket to the Codex or OpenCode supervisor, which shapes events with the code its Remote Control worker already uses. The browser renders from a pure store module and a small DOM view.

**Tech Stack:** Rust (axum 0.8 WebSocket, tokio, serde_json), Node 22 ES modules for the supervisors, vanilla JavaScript and CSS for the UI, `node --test` and `cargo test`.

**Spec:** `docs/superpowers/specs/2026-11-12-chat-core-design.md`. Read it first; this plan argues from it.

- Tests use fakes and fixtures, never a real provider account. CI commands: `node --test`, `cargo test --all --locked`, `cargo clippy --all-targets --locked -- -D warnings -D clippy::disallowed_types`.
- "Open in Claude" behaviour and the Remote Control worker code paths (`worker()` in `codex-remote.mjs`, `worker()` and `RemoteBridge` in `opencode-remote.mjs`, `claude-remote.mjs`) must not change. The Claude launch command in `spawn.rs` must not change.
- Supervisors must never write to stdout: it is the native TUI's terminal.
- Supported versions stay: Node 22+, Codex 0.162.1+, OpenCode 2.1.4+ within major 2. The Claude tap was checked against Claude Code 2.1.322.
- Mark deliberate shortcuts with a `ponytail:` comment naming the ceiling.
- The agent logs chat open, close and send without message text.
- CSS class names and ids must not match `/\.send[\s{.:-]/` or contain `send-input`; `app.js` must not contain `/api/keys`.
- Text limits: a chat message is at most 32,768 bytes after sanitizing; tool input and tool output are capped at 65,536 characters, as the bridges already cap them.

## Review Focus

Each line names a condition no spec acceptance check exercises. The test that pins it lives in the task named.

1. A transcript line that reaches disk in two writes must be delivered once, whole, not dropped as bad JSON. Task 6.
2. The same text sent twice in a row must be confirmed as two messages, each client ID once. Task 5.
3. A client that reconnects after the agent restarted, with an old position, must be told to start over and must not show duplicates. Tasks 5 and 10.
4. A session that ends while messages are held must refuse further sends and report every held message as not sent. Task 5.
5. A multi-megabyte non-conversation line in the transcript (`api-request-blob`) must be skipped without losing the records after it. Tasks 2 and 6.

## Protocol reference

Every task uses these shapes. They are decided here once.

**Events (`ev`)**, in Agent SDK message shapes:

```
{"type":"user","uuid":U,"message":{"role":"user","content":TEXT},"src":"typed"|"queued"|"steer","cid":CID?}
{"type":"assistant","uuid":U,"message":{"id":M,"role":"assistant","content":[{"type":"text","text":TEXT}]}}
{"type":"assistant","uuid":U,"message":{"id":M,"role":"assistant","content":[{"type":"tool_use","id":T,"name":N,"input":{}}]}}
{"type":"user","uuid":U,"message":{"role":"user","content":[{"type":"tool_result","tool_use_id":T,"content":TEXT,"is_error":BOOL}]}}
{"type":"result","subtype":"success"|"interrupted"|"error_during_execution","duration_ms":N?}
{"type":"cdash","subtype":"shell","uuid":U,"command":TEXT}
{"type":"cdash","subtype":"shell_output","uuid":U,"stdout":TEXT,"stderr":TEXT}
{"type":"cdash","subtype":"queued","text":TEXT}
{"type":"cdash","subtype":"retract","uuid":U}
```

`content` of a prompt may also arrive as `[{"type":"text","text":…}]` (Codex and OpenCode do this); readers accept both. A *prompt* is a `user` event whose content is not a `tool_result` list.

**Browser to agent**, `GET /api/chat?name=<cdash-name>[&after=<seq>&epoch=<id>]`, WebSocket text frames:

```
server: {"t":"hello","epoch":E,"tool":"claude"|"codex"|"opencode","first":N,"head":N,"reset":BOOL}
server: {"t":"ev","seq":N,"ev":EV}
server: {"t":"delta","id":M,"text":APPENDED}                      never stored, never replayed
server: {"t":"state","working":B,"waiting":B,"ended":B,"unreadable":B,"held":[{"id":"h1","text":TEXT}]}
server: {"t":"ack","cid":CID,"status":"held"|"sent"|"unconfirmed"|"returned"|"refused","id":"h1"?,"error":TEXT?}
server: {"t":"page","events":[{"seq":N,"ev":EV}],"more":B}
server: {"t":"reset","epoch":E}                                   conversation changed; positions restart at 1
client: {"t":"send","cid":CID,"text":TEXT}
client: {"t":"stop"}
client: {"t":"held","op":"now"|"remove","id":"h1"}
client: {"t":"page","before":N,"limit":N?}
```

`hello` is followed by the backlog as `ev` frames, then one `state` frame. `reset` is true when the client sent no `epoch` or a different one. Close code 4000 means the session ended, 4002 means the client fell behind and must reconnect with its last position.

**Agent to supervisor**, NDJSON over the unix socket named by `chat_sock` in the pane's `.native` file:

```
agent:      {"after":N,"epoch":E|null}                            first line
supervisor: {"t":"hello","epoch":E,"head":N}   then {"t":"ev","seq":N,"ev":EV}…   then {"t":"state","working":B,"waiting":B}
supervisor: {"t":"ready"}                                         history has been replayed
supervisor: {"t":"delta","id":M,"text":APPENDED}
agent:      {"t":"send","cid":CID,"text":TEXT,"steer":B}          answered by {"t":"ack","cid":CID,"ok":B,"error":TEXT?}
agent:      {"t":"stop"}
```

- [ ] **Step 3: Implement the actor.** One task owns all state and handles engine messages, client commands (an `mpsc` channel carrying a `oneshot` reply) and a 250 ms tick in one `select!` loop, so commands are serialized by construction. Frames go out on a `broadcast` channel of capacity 1024. Subscribers that arrive before `Ready` wait for it. State and rules:
  - `epoch`: 8 random bytes as hex (`getrandom`), new on `Reset`. `log: Vec<Value>`; position = index + 1.
  - `pending`: messages handed to the engine and not yet answered, each `{cid, text, at, uuid, exempt}`. `exempt` is true when the engine returned `Ok(true)` or a `cdash/queued` event with the same text was seen; exempt entries never time out.
  - **Send:** sanitize, else `refused` with the sanitizer's message. `ended` gives `refused` / `session ended`. `unreadable` gives `refused` / `cannot read this session; use Terminal`. `waiting` gives `refused` / `answer in Terminal first`. `working` gives `queue.hold` and `held` with the `id`. Otherwise deliver.
  - **Deliver(cid, text, steer):** `engine.send`; on error `refused` with the error; on success push to `pending`, ack `sent`, log `chat send <name>`.
  - **Prompt event:** the prompt's text is its string content, or the joined text of its text blocks. Match the first pending entry that has no `uuid` yet and the same text; set `ev.cid` from it and remember the event's `uuid` on it. Clear `turn_ok`.
  - **Assistant, tool result or result event:** drop every pending entry that has a `uuid`. A `result` with subtype `interrupted` calls `queue.stop_all()`; any other `result` sets `turn_ok`.
  - **Release:** after every engine message and every command, if `!working && !waiting && !unreadable && turn_ok` and every pending entry is exempt, take `queue.next_auto()` and deliver it with `steer: false`, clearing `turn_ok`. (Exempt entries are already in the tool's hands and must not block the queue.)
  - **Stop:** `queue.stop_all()` at once. If `working` or `pending` is non-empty, call `engine.stop()` and note the time.
  - **Tick:** a pending entry older than `CONFIRM_AFTER` that is not exempt and has no `uuid` is acked `unconfirmed` and dropped. `STOP_SETTLE` after a Stop, if `!working` and a pending entry that is not exempt remains, the newest such entry was handed back: call `engine.clear_input(text)`, append a `cdash/retract` event when it has a `uuid`, ack `returned`, drop it.
  - **Held now:** `queue.take`, deliver with `steer: working`. **Held remove:** `queue.take`.
  - **Reset:** new epoch, empty log and pending, broadcast `reset`. The queue is kept.
  - **Unreadable:** set the flag and broadcast state; nothing is typed into the session from then on.
  - **Ended:** ack `refused` / `session ended` for every held and pending message, clear both, broadcast state, then stop the task after the engine channel closes.
  - A `state` frame is broadcast whenever `working`, `waiting`, `ended`, `unreadable` or the held list changes.
  - `// ponytail: the whole conversation is kept in memory; page from the source by offset if sessions get large enough to matter.`
